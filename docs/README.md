# 文档索引

五篇文档各管一层，同一内容只在「唯一出处」出现一次；遇到重复陈述时，以出处表为准。

| 文件                                   | 解决什么问题                                                                      | 什么时候看                                |
| -------------------------------------- | --------------------------------------------------------------------------------- | ----------------------------------------- |
| [architecture.md](architecture.md)     | 程序怎么组织：运行结构、分层依赖、模块职责、外部写入边界、失败域                  | 想知道「为什么这么跑」「改动会波及谁」    |
| [sync-paths.md](sync-paths.md)         | 五条链路逐条的业务行为：流程、匹配、状态映射、写入字段、可见性、幂等与不写入      | 想知道「某条链路到底会写什么 / 不写什么」 |
| [github-actions.md](github-actions.md) | Actions 运行手册：触发与手动输入、Secrets、产物、名单移出规则、定向复核、排障顺序 | 要在 CI 上配置、看产物或排障              |
| [configuration.md](configuration.md)   | 全部环境变量：按能力分组，每个变量只出现一次，附默认值                            | 想改某个具体行为                          |
| [reference.md](reference.md)           | 契约层：接口边界、读取三态、reason 总表、日志哨兵、状态文件、自检等式             | 想核对「机器对得上」的东西                |

## 单一归属

| 内容                   | 唯一出处            | 其余文件的处理                 |
| ---------------------- | ------------------- | ------------------------------ |
| 状态文件（`.cache/*`） | `reference.md`      | 其他文件只留指向               |
| ⑤ 未匹配原因（9 种）   | `reference.md`      | `sync-paths.md` 只点名         |
| ④ 两 reason 的差异     | `reference.md`      | `sync-paths.md` 指向           |
| 状态映射 / 写入字段    | `sync-paths.md`     | `configuration.md` 不写行为    |
| Secrets / 手动输入     | `github-actions.md` | `README.md` 保留入口简表       |
| 自检等式与退出码       | `reference.md`      | README / architecture 各留口径 |

## 交叉引用规则

- docs 内部互相引用用同目录裸文件名（如 `[参考手册](reference.md)`）；引用根 README 用 `../README.md`。
- 改动小节标题时，先 `grep` 三个锚点引用（`标记时间策略`、`reason 总表`、`状态文件与留档`）再重命名。
